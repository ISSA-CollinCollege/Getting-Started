# Contributing to ISSA Collin College
    
    Welcome! We are excited to have you collaborate with us. This organization serves as a professional sandbox for our 
    members to sharpen their development and security skills. By contributing here, you are practicing the exact workflows 
    used by professional engineering teams worldwide.
    
## The Golden Rules
    
    1. Membership Requirement
    Contribution is exclusive to active members of the ISSA Collin College Chapter. 
    While our repositories are public for the world to see (and for you to showcase on your resume), the right to 
    contribute via Pull Request is reserved for chapter members. 
    If you are not yet a member, please reach out to the Chapter President to join.
    
    2. Open Source & Collaboration
    Everything built within this organization is Open Source. By contributing, you agree that your code will be 
    available for others to study, learn from, and improve. We prioritize collaborative growth over individual ownership.
    
    3. Professionalism & Ethics
    As members of a cybersecurity organization, we adhere to a strict code of ethics. 
    - No malicious code.
    - No plagiarism.
    - Respectful code reviews.
    - Security-first mindset (no hardcoded secrets/API keys).
    - We prefer non-AI generated code so you can better master programming practices, though AI-assistance (e.g. using 
    AI to help understand a concept, not write code for you) is permissible. You are still responsible for the code 
    you commit.
    
    
    
## The Contribution Workflow
    
    We follow the GitHub Flow. To maintain the stability of our projects, no one pushes directly to the main branch. 
    
    The Step-by-Step Process:
    
    1.  Fork the Repository: Create your own copy of the project by clicking the "Fork" button in the top right.
    2.  Clone Your Fork: Download your copy to your local machine.
        
        git clone https://github.com/your-username/project-name.git
        
    3.  Create a Feature Branch: Never work on main. Create a descriptive branch for your specific change.
        
        git checkout -b feature/added-login-validation
        
    4.  Commit Your Changes: Write clear, concise commit messages.
        - Bad: fixed stuff
        - Good: fix: resolve null pointer exception in user validation logic
    5.  Push to Your Fork: Send your changes back up to your GitHub account.
        
        git push origin feature/added-login-validation
        
    6.  Open a Pull Request (PR): 
        - Go to the original ISSA repository.
        - Click "New Pull Request."
        - Describe what you changed and why you changed it.
    7.  The Review Process: A maintainer will review your code. They may ask for changes. This is the most important 
    part of the learning process—embrace the feedback!
    8.  Merge: Once approved, your code will be merged into the main branch.
    
    
    
## Need Help?
    If you are stuck on the Git process or aren't sure where to start, don't hesitate to ask in the chapter Discord or 
    reach out to a maintainer. 
    We were all beginners once; the only "bad" question is the one you didn't ask.
